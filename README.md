# Gramwright Lab — журнал проверки гипотез

Сайт: **https://XSlaidx.github.io/gramwright-lab** · канал: [@gramwright_lab](https://t.me/gramwright_lab)

Здесь лежат **посты в markdown**, а не готовая страница. Причина простая: журнал проверок имеет
смысл ровно потому, что его нельзя тихо переписать. В этом репозитории видно дату каждой правки,
диффы и то, менялись ли числа после публикации — история коммитов и есть доказательство.

## Как это устроено

```
posts/*.md      # источник: заголовок, дата, ссылка на обсуждение в front matter + текст
build.py        # генератор: markdown -> docs/ (только стандартная библиотека)
docs/           # сгенерированный сайт, его отдаёт GitHub Pages (ветка main, папка /docs)
```

Правила, которые соблюдаются в постах:

1. **Числа — только из журнала стенда.** Если числа нет в данных, в тексте будет «данных нет».
2. **Никаких обещаний доходности и сигналов.** Тон — бортовой журнал инженера-испытателя.
3. **Отрицательный результат — тоже результат**: он публикуется так же, как положительный.
4. Каждый пост заканчивается строкой «Не инвестиционная рекомендация.»

Код, о котором пишутся посты, открыт: [XSlaidx/truth-engine](https://github.com/XSlaidx/truth-engine) —
предохранители, append-only журнал и независимый аудитор, который пересчитывает записи и падает с
ненулевым кодом, если журнал ему не нравится.

## Локальная сборка

```bash
python build.py           # пересобрать docs/
python build.py --check   # упасть, если docs/ не совпадает с пересборкой (используется в CI)
```

Зависимостей нет: генератор держится на стандартной библиотеке, чтобы сайт можно было собрать на
любой машине через пять лет без «а помнишь, там был webpack».

## Публикация

1. Добавить `posts/ГГГГ-ММ-ДД-слаг.md` с front matter (`title`, `date`, `telegram`, `tags`, `summary`).
2. `python build.py` → закоммитить и пост, и `docs/`.
3. CI проверит, что `docs/` соответствует постам, и Pages обновится сам после пуша в `main`.
